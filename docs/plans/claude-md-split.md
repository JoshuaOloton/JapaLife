# Plan: slim CLAUDE.md, move history and detail into docs/

## Context

CLAUDE.md is 56 KB / 328 lines and loads in full every session. About 39 KB of it is record, not instruction: the Phase 1 slice history, "Known limits" (25 KB), "Look-ahead" and the Phase 2 plan. Important rules get buried. Goal: CLAUDE.md keeps the rules, the current phase and the open decisions (about 20 KB); the rest moves, **word for word**, into linked files under `docs/`.

The catch: "Known limits" is not only history. About 20 of its entries are rules that code must follow (for example "game code calls `WalletService`, never `Ledger`", "every notice goes through `InboxService.deliver`"). Moving them out wholesale would hide them. So they are distilled into one-line rules that stay in CLAUDE.md, each linking to the full entry.

## What CLAUDE.md keeps

Unchanged: Project, The journey, Realism rules, Stack, Repo layout, Commands, Non-negotiable rules, Tone and content, Safety and compliance, Code conventions, Working with me, How to work in this repo, Open decisions.

Changed:
1. **New section "Rules from the build"** (after Code conventions), about 3.5 KB. One line per rule, grouped, each ending with a link to its full entry in `docs/known-limits.md`:
   - **Money:** call `WalletService`, never `Ledger`; never check `getBalance` then spend (call `debit`); idempotency keys come from the event (`shift:<playerId>:<shiftId>`), never random. Only `Ledger` writes `Transaction` rows; the ledger is append-only (fix mistakes with reversing entries). Don't expose `transfer` until the money sharing controls are decided. A new faucet or sink needs its reason in `packages/shared/src/economy.ts`, its amount in `content/`, and its ceiling in `earningCeilings`, or `BalanceWatch` flags every use. Money is `bigint`: no money maths in `number`; send balances as numbers or strings. Wallets never go negative, so loans need their own model.
   - **Server:** every intent through `parseIntent` and the per-player `KeyedMutex`. Every notice through `InboxService.deliver`, never `client.send` or `NoticeBus.publish`. Logging through `logError`, never `console.error(error)`. Game state lives in Postgres, not the room; meter changes go through `PlayerService.applyChange` or `saveNeeds`. Anything that must happen once (a late fee, an event answer) is claimed with a conditional update before it acts.
   - **World and collision:** `moveWithCollisions` is shared by server and client; the city-file footprint is the collision truth; a building's model must fill its footprint, and the footprint is sized to the scaled model, never the model stretched to the box. `content/models/catalog.json` is generated by `pnpm assets`; never hand-edit it. No Rapier for player movement.
   - **Client:** only APIs that work on plain http (`crypto.getRandomValues`, not `randomUUID`; no clipboard or service workers). Register new server messages in `MessageBuffer`. Prices reach the client in the `interaction` reply; the client has no copy of `content/`.
   - **Tooling:** run `pnpm db:generate` after a Prisma schema change. Changing `packages/shared` needs a `next dev` restart; changing `content/` needs a server restart; changing copy needs a client rebuild. TypeScript stays on `~6.0` until `typescript-eslint` supports 7.
   - Closing line: when you add a known limit, put it in `docs/known-limits.md`; if it is a rule code must follow, also add its one-liner here.
